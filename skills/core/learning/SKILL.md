# learning

**Two lenses, one front door.** Pick by the verb:

| You are trying to… | Lens | First move |
|---|---|---|
| **Learn** a skill / tool / language / domain fast | **Ultralearning** (Young) | Metalearning: ask Why / What / How; split Concepts·Facts·Procedures; benchmark the field |
| **Solve** a specific hard problem you're stuck on | **Polya** (How to Solve It) | Name the principal parts (unknown · data · condition), then search for a related problem |

When in doubt: *acquiring a capability* → Ultralearning. *Cracking one problem* → Polya. They chain — Ultralearning's **Drill** principle is "find the bottleneck subskill"; Polya is how you then crack that subskill when it resists.

## Ultralearning — the 9 principles (Scott Young)

Intense, self-directed skill acquisition. Run as a *project*: map it, then attack it directly.

1. **Metalearning** — first draw a map (field, standards, resources, bottlenecks). Spend ~10% of total time researching *how* to learn it before diving in.
2. **Focus** — protect attention; unfocused time doesn't count. Five-minute rule to start; Pomodoro to sustain.
3. **Directness** — practice the actual task, not a convenient proxy. Transfer is weak; skip the inert intermediary.
4. **Drill** — isolate the weakest subskill, improve it, reintegrate. (This is where Polya plugs in.)
5. **Retrieval** — test yourself *before* you feel ready. Recall is a learning method, not just assessment.
6. **Feedback** — get correction early and often; separate signal from ego-pain and noise.
7. **Retention** — schedule review + real use so it survives the sprint. Spacing beats cramming.
8. **Intuition** — dig into *why* via the Feynman technique (explain it simply); don't fake understanding.
9. **Experimentation** — treat methods as hypotheses; when you plateau, test new tactics.

## Polya — the 4-phase method (How to Solve It)

Convert stuckness into structured search. Ask the canonical question at each phase.

| Phase | Ask yourself |
|---|---|
| **Understand the Problem** | What is the unknown? The data? The condition? Can I restate it plainly? Can I draw it? |
| **Devise a Plan** | Do I know a *related* problem? Can I use its result/method? Can I solve an easier/special case first? Did I use all the data? |
| **Carry Out the Plan** | Is each step correct? Can I *prove* each step, not just believe it? |
| **Look Back** | Can I check the result? Derive it differently? **Reuse the method elsewhere?** (Most people skip this — it's where the compounding is.) |

Heuristic devices when the direct attack stalls: **analogy · auxiliary problem · specialization · generalization · working backwards · decompose-and-recombine · reductio ad absurdum.** (Full set in Pólya's Part III, “Short Dictionary of Heuristic”.)
